# Cooperative kinematic integration experiment

This is a configurable, simulator-neutral integration milestone, not a Gazebo/Isaac/CARLA physics simulation. The same loop uses the shared evidence store, mission orchestrator, A* and vehicle model registry. A synthetic drone, rover and road vehicle publish states and range-limited exact object-center observations; the planner consumes shared evidence. Tasks complete only when simulated positions reach configured goals. No fixed waypoints are used. The declared free-map prior is not learned from sensors. Local routes are planar with altitude-aware obstacle projection; vertical control is limited, not a 3D flight planner.

Run docker compose run --build --rm cooperative-kinematic. Output: semantic_data/outbox/cooperative_kinematic.json. Completion metrics are measured only when executed; the reference scenario may fail to reach goals due to sampling, conservative margins or local minima. There is no physical actuator output.

A separate synthetic truth guard checks sampled arcs against static obstacles and conservative peer chord reservations. It is not the independent C++ RTA and not a certified collision checker. The current C++ ROS service is a sim-rover-specific assessment interface, with caller-reported dynamic peaks and simplified threats. Do not silently use it for cars or drones. The next integration requires vehicle-specific C++ profiles, independent timestamped telemetry, complete threat evidence, and a simulator-only execution gate. This milestone deliberately reports cpp_rta_connected=false.

Limitations: single-process kinematic loop, no DDS exchange in this experiment, no learned model inference, no actual sensor rendering, no realistic acceleration/braking, no road rules or lane topology, no moving obstacles, no network failures, no continuous-time proof. Ground truth guard and free prior are simulation scaffolding. Unit tests and full scenario require execution before claiming success.
